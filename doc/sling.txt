1. INTRODUCTION                                                  *sling-intro*

sling sends the current line or visual selection to a CLI agent (Claude Code
by default) running in a tmux pane. A prompt and a `@file#L10-20` reference
are pasted into the agent's input. If no agent pane exists in the current
tmux window, one is opened in a split.

The plugin works without configuration: keymaps and |:Sling| are registered
on startup. Call |sling.setup()| only to change the defaults.

==============================================================================
2. REQUIREMENTS                                           *sling-requirements*

- Neovim 0.10+
- tmux, with Neovim running inside a tmux session (for tmux targets)
- `claude` (Claude Code) on $PATH, or another CLI configured as a target

==============================================================================
3. USAGE                                                         *sling-usage*

1. Put the cursor on a line, or select lines in visual mode.
2. Press `<leader>ap`, type a prompt and send it with <C-s> (<CR> adds a
   line in insert mode, sends in normal mode).
3. The prompt is pasted into the agent pane, but not submitted. Press <CR>
   there to send it, or use `<leader>aP` to submit right away.

A pane already running the agent in the same tmux window is reused.

==============================================================================
4. COMMANDS                                                   *sling-commands*

                                                                      *:Sling*
:[range]Sling [action]
    Run [action] (default: `ask`) on [range], or on the cursor line when no
    range is given. Completes action names.

==============================================================================
5. DEFAULT ACTIONS                                             *sling-actions*

All default keymaps work in normal mode (cursor line) and visual mode
(selection).

  Key           Action        Description ~
  `<leader>ap`    `ask`           prompt for input, prefill it (no submit)
  `<leader>aP`    `ask_submit`    prompt for input, submit it
  `<leader>aa`    `add`           paste only the `@file#L1-5` reference
  `<leader>ac`    `collect`       add the reference to the scratch, open it
  `<leader>as`    `scratch`       open the scratch
  `<leader>ad`    `fix`           send the diagnostics of the range

                                                               *sling-scratch*
The scratch collects references and notes for one prompt. New entries are
appended below, separated by an empty line. It is saved per working
directory under `stdpath("state")/sling/scratch`. <Esc> closes and keeps
it, <C-l> empties it (`u` undoes), <C-s> sends it like `ask` and clears it
once it arrived; a failed send keeps it.

                                                                *sling-model*
The model picked for the target shows in the title of the prompt and
scratch window, `model_key` (<C-t>) cycles through the target's `models`.
The pick is kept for the session and used by all actions of that target.
Targets without `models` (e.g. clipboard) have no picker.
A new pane starts with `cmd model_flag <id>`; a running pane not known to
run the model gets `model_switch` typed first. That happens on the first
send to a pane started by hand, so its input should be empty then.

6. CONFIGURATION                                                *sling-config*
                                                               *sling.setup()*
sling.setup({opts})
    Merge {opts} into the defaults and (re)register keymaps and |:Sling|.
    Optional. Can be called again; keymaps of the previous call are removed.

Defaults: >lua
    require("sling").setup({
      -- used by actions that don't set their own
      template = "{input}\n\n{ref}",
      target = "claude",
      submit = false,
      -- prompt window: multi-line, wraps at `width`, grows up to
      -- `max_height`. <C-s> submits (any mode), <CR> submits in normal
      -- mode, <Esc>/q cancels
      input = { width = 80, min_height = 3, max_height = 15 },
      -- scratch window, same fields as `input`
      scratch = { width = 100, min_height = 15, max_height = 30 },
      -- cycles the target's `models` in the prompt and scratch window
      model_key = "<C-t>",
      targets = {
        claude = {
          type = "tmux",
          cmd = "claude",
          split = { "-h" },
          reuse = true,
          match = function(pane)
            return pane.command == "claude"
              or pane.title:find("Claude Code", 1, true) ~= nil
          end,
          ready = "Claude Code v",
          ready_timeout = 15000,
          focus = true,
          models = {
            { name = "Opus 5.5", id = "claude-opus-5-5" },
            { name = "Fable 5.2", id = "claude-fable-5-2" },
            { name = "Sonnet 5.5", id = "claude-sonnet-5-5" },
          },
          model_flag = "--model",
          model_switch = "/model {model}",
        },
        clipboard = { type = "clipboard" },
      },
      actions = { --[[ see |sling-actions| ]] },
      vars = {},
      trees = {},
    })
<
                                                              *sling-template*
template ~
    Default prompt template. `{name}` placeholders are replaced, see
    |sling-variables|. Unknown placeholders are left as is.

target ~
    Name of the default target in `targets`.

submit ~
    Default for actions: press <CR> after pasting.

vars ~
    Extra template variables, `name -> fun(ctx): string`: >lua
    vars = {
      branch = function()
        return vim.trim(vim.fn.system("git branch --show-current"))
      end,
    }
<

trees ~                                                          *sling-trees*
    In a file tree the entry under the cursor is used instead of lines,
    `{ref}` becomes `@path` (folders end in `/`). Built in: neo-tree, snacks
    explorer, nvim-tree, oil. In visual mode every entry in the selection is
    used, one `@path` per line. Add more as `filetype -> fun(line): string?`,
    the path of the entry on that line: >lua
    trees = {
      minifiles = function(line)
        return (MiniFiles.get_fs_entry(0, line) or {}).path
      end,
    }
<
------------------------------------------------------------------------------
ACTIONS                                                 *sling-config-actions*

`actions` maps a name to an action table, or `false` to disable a default.
Tables are merged into the defaults, so changing one field is enough: >lua
    actions = {
      ask = { keys = "<leader>kp" },
      fix = false,
      tests = {
        template = "Write tests for @{file}#L{lines}",
        submit = true,
        keys = "<leader>kt",
        desc = "Write tests",
      },
    }
<
Action fields:

  template  (string)           prompt template, default: `template`
  target    (string)           target name, default: `target`
  input     (boolean|string)   ask for `{input}` first; a string is used as
                               the input title. Empty input cancels.
  scratch   (boolean|string)   open the |sling-scratch| instead; `template`
                               is appended first. A string is the title.
  submit    (boolean)          press <CR> after pasting, default: `submit`
  keys      (string|string[])  keymap(s)
  mode      (string|string[])  modes for `keys`, default: `{ "n", "x" }`
  desc      (string)           keymap description
  model     (string)           model id, skips the |sling-model| picker

------------------------------------------------------------------------------
TARGETS                                                 *sling-config-targets*

`targets` maps a name to a target table or a function.

`type = "tmux"`                                            *sling-target-tmux*
    Paste into a tmux pane in the current window, opening one when needed.

    cmd            (string)    command started in a new pane
    split          (string[])  args for `tmux split-window`,
                               e.g. `{ "-h", "-l", "40%" }`
    reuse          (boolean)   reuse an existing pane instead of splitting
    match          (function)  `fun(pane): boolean`, recognises panes started
                               by hand; `pane` is `{ id, command, title }`
    ready          (string)    Lua pattern in the pane content that tells a
                               new pane is ready for input
    ready_timeout  (integer)   ms to wait for `ready`
    focus          (boolean)   move to the pane after sending
    models         (table)     |sling-model| list, first is the default;
                               `{ name, id }` tables or id strings. Replaces
                               the default list instead of merging
    model_flag     (string)    appended to `cmd` with the id in a new pane
    model_switch   (string)    typed into a running pane, `{model}` is the id

`type = "clipboard"`                                  *sling-target-clipboard*
    Copy the prompt to the `+` register.

Function                                               *sling-target-function*
    `fun(prompt: string, ctx: table, action: table)`. Return `false` to mark
    the send as failed, e.g. so |sling-scratch| is kept. >lua
    targets = {
      log = function(prompt) print(prompt) end,
    }
<
------------------------------------------------------------------------------
TEMPLATE VARIABLES                                           *sling-variables*

  `{input}`        text typed at the prompt (actions with `input`)
  `{ref}`          `@file#L1-5`, or `@path` in a |sling-trees| entry
  `{file}`         file path relative to the cwd
  `{abs_file}`     absolute file path
  `{dir}`          directory of the file, relative to the cwd
  `{cwd}`          current working directory
  `{filetype}`     'filetype' of the buffer
  `{lines}`        `10` or `10-20`
  `{start_line}`   first line of the range
  `{end_line}`     last line of the range
  `{selection}`    selected text (whole lines for a command range)
  `{diagnostics}`  diagnostics in the range, one per line

==============================================================================
7. LUA API                                                         *sling-api*

                                                                 *sling.run()*
sling.run({action}, {overrides}, {range})
    Run an action by name, or an ad-hoc action table. {overrides} is merged
    into the action. {range} is `{ first, last }` line numbers. >lua
    require("sling").run("ask")
    require("sling").run("ask", { submit = true })
    require("sling").run("ask", { model = "claude-sonnet-5-5" })
    require("sling").run({ template = "Review", target = "clipboard" })
<
==============================================================================
8. HEALTH                                                       *sling-health*

`:checkhealth sling` checks the Neovim version, tmux, the commands of tmux
targets and that every action points to an existing target.
